# GPU-окно — сбор логов (runbook для запуска ВРУЧНУЮ при чистом окне)

Назначение: один пакет команд, который собирает ВСЕ отложенные GPU-логи за
один заход на сервере (4× V100-SXM2), пока окно чистое. Ничего не выдумывает:
шаг без входных данных/окна → честная запись «pending, причина» в сводку,
прогон продолжается.

## Что собирает (соответствие pending-списку)

| Шаг | Что даёт | Какой pending закрывает |
|---|---|---|
| A. NCCL scaling | allreduce-латентность TP1/TP2/TP4, scaling-фактор | NCCL-окно [R6] (rounds 4-8) |
| B. tiers GPU DMA smoke | cudaMemcpyAsync H→D/D→H на V100 | VRAM-слоты/пиновка (ADR-08) на GPU |
| C. Конвертация layout | stell-tier layout реального чекпоинта (~16 ГиБ, ~11 мин) | вход для D/E |
| D. per-group bench матрица | hit-rate prefetch + p95 пауз слоя: {buffered,odirect}×{k=1,4}, БЮДЖЕТ слотов (давление eviction) | спека Потока B: p95 ≤ 5 мс, prefetch ≥ 60% на MoE > VRAM |
| E. Декод-контур | контрольные логиты ПОБИТОВО vs прямой лоадер + wall/token | точка регрессии tiers на GPU-окне |
| F. Quality gates | PPL/GSM8K/HumanEval через ABI (--live --real) | full-гейт §5 без co-tenancy пометки |
| G. Реальные чекпоинты (GLM/Qwen3_5Moe/dense) | пробы конвертера на новых архитектурах | pending ADR-09 — только если вы положили чекпоинты в ~/models |

## Где запускать

Только на сервере, в git-клоне (протокол server-env: scp-артефакты запрещены),
в корне репо:

```bash
ssh -p 2214 192.168.1.114
cd ~/Code/stell-llm            # или путь к клону
git pull                       # ветка/мастер с этим пакетом
export PATH=~/.local/stell-conda/envs/stell/bin:$PATH
```

## Быстрый старт

```bash
# 1. Проверка окна (НЕ запускает замеры — только диагностика):
bash bench/gpu-window/preflight.sh
#    ПРИМЕЧАНИЕ: non-V100 карты (RTX 2060 и др.) исключены из критериев —
#    они не участвуют и окну не мешают.

# 2. Полный прогон (сам проверит окно ещё раз перед GPU-шагами):
bash bench/gpu-window/run-gpu-window.sh
```

Если сборка STELL_CUDA=ON не прошла — оркестратор напечатает хвост
logs/build.log прямо в сводку с подсказками (частая причина: nccl.h вне
/usr/include и /usr/local/cuda/include → передать
-DSTELL_NCCL_INCLUDE=<каталог>; или build/gpu остался от CPU-конфигурации →
rm -rf build/gpu).

Всё падает в `bench/results/<UTC-date>-gpu-window/`:
`environment.txt` (снапшот железа/процессов), `logs/*.log` (сырые прогоны),
`report.md` (сводка: что измерено / что pending и почему).

## Условия чистого окна (preflight проверяет)

1. На каждой из ≥4 **V100-SXM2** (участвуют ТОЛЬКО они; прочие карты —
   RTX 2060 и т.п. — не-участники и из критериев исключены): нет чужих
   процессов (nvidia-smi --query-compute-apps), свободно ≥ 30 GiB VRAM.
   Если co-тenant жив (держит ~21-30 ГиБ на V100) — окна НЕТ; скрипт это
   зафиксирует и уйдёт в pending, НЕ трогая чужую память.
2. NVLink-топология доступна (nvidia-smi topo -m) — для сравнения с server-env.
3. Свободно ≥ 20 ГиБ на NVMe под layout (+ старые layout удалить).
4. Сборка STELL_CUDA=ON возможна (CUDA toolkit + NCCL в окружении stell).

## Переменные окружения (все опциональные)

- `STELL_GPUWINDOW_MODEL` — путь к реальному чекпоинту для C-E
  (дефолт `~/models/qwen3-30b-a3b`; если пути нет — автопоиск по
  ~/models/*/config.json среди архитектур конвертера, найденное
  перечисляется в сводке).
- `STELL_GPUWINDOW_PYTHON` — python для quality gates (дефолт: conda-env
  serve, затем python3 из PATH).
- `STELL_GPUWINDOW_EXTRA_MODELS` — каталог с доп. чекпоинтами для шага G
  (GLM/Qwen3_5Moe/dense — то, чего ждёт ADR-09; ищет config.json рекурсивно).
- `STELL_GPUWINDOW_RESULTS` — куда класть артефакты (дефолт: bench/results).
- `STELL_TIER_VRAM_SLOTS` — бюджет слотов для шага D (дефолт: матрица
  24/48/96 — три уровня давления eviction на 18867 группах).

## Что прислать обратно

Весь каталог `bench/results/<date>-gpu-window/` (логи + report.md) —
worker заберёт, сверит с критериями (p95 ≤ 5 мс, prefetch ≥ 60%, побитовое
равенство логитов) и вольёт артефакт в репо с provenance (окно чистое —
пометка co-tenancy СНИМАЕТСЯ, в отличие от прошлых прогонов).

## Честность

- Скрипты не имитируют результаты: шаг без бинарника/входов/окна → запись
  «PENDING: причина» в report.md и exit 0 в конце (сводка всё перечислит).
- Сравнения — только внутри одного контракта (одно окно, одно железо);
  перекрёстные сравнения с CPU/co-tenancy прогонами помечаются как
  «разные контракты».
- Внешние имена железа/процессов окружения — только в логах окружения,
  не в коде (правило spec, прецедент I1).
