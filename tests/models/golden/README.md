# Golden-тест логитов — каркас раунда 1 (ADR-09 §4)

## Статус: ПЕНДИНГ ПРОГОНА ПРОТИВ HF

Локально нет весов и нет GPU; сервер занят чужим процессом strata. Каркас
сравнения готов (`golden_logits.cpp`) и честно печатает SKIP, пока нет
фикстур. План: сгенерировать референсы на сервере, заполнить фикстуры.

## Фикстура `logits_ref.json` (схема — logits_ref.schema.json)

```json
{
  "schema": "1.0",
  "model": "glm-class",
  "profile": "NVFP4",            // F16 | NVFP4 | W4A16 (ADR-03)
  "path": "loader",              // loader | stelltier | tiering_nvme_miss (ADR-09 §4)
  "prompt_tokens": [1, 2, 3],
  "seed": 0,                     // bench-контракт PLAN.md §5
  "greedy": true,                // T=1
  "tolerance_rel": 0.001,        // FP16-профиль; для NVFP4/W4A16 — свои пороги
  "logits_ref": [ ... ],         // эталон HF (последний слой, один decode-шаг)
  "logits_tested": [ ... ]       // заполняется прогоном stell-llm; поле опционально
}
```

## Правила сравнения (реализованы в golden_logits.cpp)

- rel-ошибка по каждому элементу: |ref − tested| / max(|ref|, |tested|, 1) ≤ tolerance_rel;
- три пути прогоняются с тем же `seed`/входом: `loader`, `stelltier`, `tiering_nvme_miss` —
  логиты обязаны совпадать с входом того же профиля (tiering не меняет вычисление);
- отсутствие `logits_tested` → SKIP (не молчаливый успех «как будто проверено»).

## Допуски (ADR-09 §4)

- F16: rel ≤ 1e-3;
- NVFP4 / W4A16: порог фиксируется в фикстуре после калибровки против
  HF-референса на сервере (предварительно ~1e-2, уточняется).

## Как включить тест (после появления весов)

1. На сервере сгенерировать HF-референс (logits последнего слоя) для каждой
   архитектуры реестра при фиксированном входе;
2. положить `logits_ref.json` в этот каталог;
3. `ctest --test-dir build/cpu -R golden_logits` начнёт сравнение автоматически.
