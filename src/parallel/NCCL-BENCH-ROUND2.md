# parallel — замер latency allreduce/allgather (NCCL-backend, раунд 2)

Сервер: 4×V100-SXM2-32GB (NVLink), cuda 12.8, NCCL 2.26.2, сборка
`STELL_CUDA=ON` + libnccl (`/usr/lib/x86_64-linux-gnu/libnccl.so`).
Тест: `tests/parallel/test_nccl_gpu.cpp` (бинарник `test_parallel_gpu`,
ctest-имя `parallel_gpu`). Co-tenancy честная: чужой процесс strata держит
~21–30 GB VRAM на каждой V100 (свободно 2.0–11.2 GB), поэтому числа —
под нагрузкой, не «чистые» NVLink-латентности; разброс между прогонами
значительный (медианы по 100 итерациям на прогон).

## Корректность (пройдено на каждом прогоне)

- allreduce F32: по всем размерам 1 … 262144 элементов — битовое равенство
  ожидаемой сумме (значения целые < 2^22);
- allgather F32: конкатенация send-паттернов по ранкам — битовое равенство;
- 2 ранка (GPU 0,1) и 4 ранка (GPU 0–3) — обе топологии зелёные.

## TP2 (2 ранка, GPU 0+1), медианы µs по 100 итерациям

| Размер (floats) | типичный | наблюдаемый разброс по прогонам |
|---|---|---|
| 1 | ~20–50 µs | 18.7 … 2134 (шум strata) |
| 64 | ~20–45 µs | 18.6 … 1931 |
| 256 | ~20–200 µs | 18.7 … 2019 |
| 1024 | ~19–730 µs | 18.7 … 2006 |
| 4096 | ~22–1100 µs | 21.7 … 1859 |
| 16384 | ~21–24 µs | 20.7 … 186 |
| 65536 | ~33 µs | 32.6 … 2011 |
| 262144 | ~68–95 µs | 67.6 … 1898 |

Характеристика: при свободной шине медианы ~20–35 µs на размеры ≤ 256 KB и
~68 µs на 1 MB (TP2); сильные всплески (0.1–2.3 ms) — контенанс с strata
(VRAM-порты/SM заняты чужим процессом).

## TP4 (4 ранка, GPU 0–3), медианы µs

| Размер | типичный | наблюдаемый |
|---|---|---|
| 1 | ~2400 µs | (контенанс) |
| 16384 | ~213 µs | 95.8 |
| 262144 | ~96–251 µs | 95.8 … 2514 |

TP4 на 1 MB: 96 µs (лучший прогон) против ~68 µs TP2 — масштабирование
под контенансом нелинейно; чистый прогон возможен только вне co-tenancy
(доступен только RTX 2060 без NVLink — для TP-латентности не годится).

## Что НЕ сделано (честно, по состоянию раунда 2 задачи T-20261017200354)

- expert_alltoall (NCCL): **реализован в раунде 2** (обмен счётчиками через
  ncclAllGather + байтовый p2p ncclSend/ncclRecv, token_elems = ширина токена);
  GPU-валидация — pending: worker прогонит после merge (co-tenancy — честная).
- kv_stream (NCCL): **реализован в раунде 2** (ncclSend/ncclRecv по кольцу на
  отдельной kv-комме, фоновый приёмник, неблокирующий pop); GPU-валидация —
  pending: worker прогонит после merge.
- E4M3-редукция через F32-стадию: host-конвертация реализована, но не гонялась
  на GPU (нужны device-ядра kernels).
