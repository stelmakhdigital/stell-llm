## 1. [R1-интеграция] Биндинг `stell_logits`

- `python/stell_serve/engine.py`: символ `stell_logits` привязан через
  getattr (ABI-совместимое расширение round 2 по планировщику Q1 — тот же
  приём, что `stell_step`); контракт:
  request `{"prompt_tokens":[…], "positions":"last"|"all"}` → ответ
  `{"logits":[[…]],"n_positions":P,"n_vocab":V}`, возврат 0/-1, при ошибке
  `{"error":…}` в out_json; строки malloc — `free()` вызывающим (конвенция
  ADR-11 §1, тот же `_release_ptr`, что для остальных строк движка).
- **Классификация — строго по наличию символа в .so** (`getattr`;
  `supports_logits`): без символа `logits()` даёт честную EngineError
  («включится после merge core [R1]»), никаких догадок по имени файла.
- Модель для логитов загружается средствами движка (cfg `runner:"ops"`,
  `model.description`/`model.weights` → реальные веса tests/models/fixtures,
  weights_format safetensors) — проверено живьём на ABI-копии:
  mini_dense загружается и жадно декодирует (токены 4,2,2 = golden greedy).
- Тесты: `tests/serve/test_logits_binding.py` — stub-.so с минимальным ABI +
  `stell_logits` (C-исходник компилируется в conftest-фикстуре): подписи
  ctypes, malloc/free smoke (64 повторных вызова), pass-through
  prompt_tokens/positions, контракт ошибки rc=-1 + `{"error":…}`.
  **Честный SKIP** теста против реального движка (golden-сверка rel ≤ 1e-6),
  пока символа нет в собранной .so — включится после merge core
  автоматически (гейт по наличию символа).

## 2. [R2-интеграция] Семантика `stell_cancel` 0/-1

- `engine.py` `cancel()` приведён к конвенции ADR-11 (планировщик Q2):
  **0 = успех, -1 = сессия не найдена/уже закрыта**; mock уже 0/-1.
- Legacy-совместимость (реальный движок pre-merge возвращает 1/0 —
  `scheduler.cancel → bool`): legacy-сборка распознаётся по отсутствию
  `stell_logits` (оба изменения входят в один merge core [R1]+[R2]);
  после merge — единый путь 0/-1. Расхождение кодов зафиксировано здесь и
  в docstring; src/engine (capi.cpp:252) НЕ редактировался (чужая зона).
- Тесты: `tests/serve/test_cancel_semantics.py` — raw ABI: активная → 0,
  несуществующая → -1, закрытая → -1; биндинг: активная без ошибки,
  неизвестная → EngineError; следующий poll → finish reason="cancelled",
  затем сессия закрыта (poll → 0 событий); `cancelled_total` в
  engine-метриках и в serve-секции /metrics инкрементируется; повторная
  отмена закрытой сессии счётчик не растит. Контракт 0/-1 на РЕАЛЬНОМ
  движке — честный SKIP до merge core (гейт — наличие `stell_logits`).

## 3. Качество-гейты живьём (через логиты)

- `src/bench/stell_bench/quality_gates_runner.py` — режим `--live`:
  - источник логитов `abi:stell_logits` (канон, через биндинг, модель —
    средствами движка) и честный fallback `golden-ref` (независимый
    Python-референс `tests/models/golden/generate_golden.py`, тот, что
    сгенерировал golden-фикстуры; сверен с HF ~1.5e-7) — до merge core
    ABI-символа в .so нет, поэтому первый живой прогон выполнен через
    fallback с явным provenance; после merge core автоматически ABI;
  - **PPL** по logprob позиций (`"positions":"all"`, teacher-forcing):
    `PPL = exp(mean(-log P(tok[i+1])))` по позициям предсказания
    (`ppl_from_logits` — чистый Python softmax/logprob, стабильно через
    max); последняя позиция промпта не предсказывает известный токен и
    не входит (127 позиций из 128 токенов);
  - **GSM8K-32**: жадное декодирование через логиты (argmax, ничья →
    меньший индекс — конвенция golden); корректность — последнее число в
    декодированном тексте против ответа (БЕЗ исполнения — вычислимо
    честно, реализовано);
  - **HumanEval-32**: честный pending — корректность требует ИСПОЛНЕНИЯ
    сгенерированного кода (unit-тесты), а исполнения кода в runner нет
    (песочница/изоляция не входят в раунд).
- Честные пометки: mini-фикстуры (vocab=16, byte-токенизатор движка) не
  являются языковыми моделями → детерминированная проекция байта → токен
  (b % vocab), обратная карта id → текст (цифры < 10 → цифра, иначе
  разделитель); полученные числа — МЕХАНИЧЕСКИЕ базовые референсы
  пайплайна (точки регрессии), не оценка качества LLM.
- Параметры прогона зафиксированы: PPL — первые 128 токенов
  фиксированного текста (`ppl_text.txt`); GSM8K — вопрос ≤ 64 токенов,
  ≤ 16 шагов декода; seed-детерминизм датасетов — 42/32 (без изменений).
- **Базовые референсы** (первый живой прогон, 2026-10-19,
  `bench/results/20261019-quality-gates-live/`, коммитится):

  | гейт | mini_dense | mini_moe |
  |---|---|---|
  | ppl_fixed_text | 18.3928 (mean_nll 2.911957) | 30.0858 (mean_nll 3.404053) |
  | gsm8k_32 | 0.0625 (2/32) | 0.0 (0/32) |
  | humaneval_32 | pending | pending |

- Тесты: `tests/serve/test_quality_gates_live.py` — математика PPL на
  синтетических логитах с известными значениями (равномерные → PPL=vocab,
  one-hot → PPL≈1), тай-брейк argmax, проекция/детокенизация, извлечение
  ответа, golden-ref воспроизводит golden-логиты (rel ≤ 1e-6), семантика
  `positions="all"` (строка i = логиты последней позиции префикса),
  ABI-путь поверх stub-.so, auto/abi/golden-ref выбор источника,
  живые гейты end-to-end (ppl/gsm8k не pending, humaneval pending).
- numpy добавлен в `python/requirements.txt` и в serve-env (нужен только

## 6. Ключевые решения

1. **Классификация kind/доступности — по наличию символа** (getattr),
   как у `stell_step`; никаких догадок по имени .so.
2. **Legacy-cancel** (1/0 у реального движка pre-merge) распознаётся по
   отсутствию `stell_logits` — оба изменения приходят одним merge core;
   после merge ветка legacy мертва сама собой (удалить одну строку).
3. **PPL — teacher-forcing по `"positions":"all"`**: PPL =
   exp(mean(-log P(tok[i+1]))), 127 позиций из 128 токенов; softmax/logprob
   в runner (чистый Python) — движок отдаёт только логиты, контракта не
   ломает.
4. **Fallback-источник логитов** (golden-ref) — чтобы гейты были живьём
   уже сейчас; числа помечены provenance и после merge core автоматически
   пересчитаются через ABI.
5. **Проекция байта → vocab** (b % 16) — единственный способ прогнать
   фиксированный текст через mini-фикстуры; зафиксирована как механический
   базовый референс, не языковая PPL.
6. **HumanEval — pending с причиной** (исполнение кода), GSM8K —
   реализован честно (сопоставление чисел без исполнения).
