# ADR-03: Форматы весов — safetensors + GGUF + собственный «stell-tier»

- **Статус:** Принято (PLAN.md §3)
- **Связано:** ADR-09 (реестр и загрузчик), ADR-12 (stell-tier layout)

## Контекст

Поддержка «любой модели» требует входных форматов, которые реально существуют
в экосистеме HF/локальных сборок, плюс собственный формат для NVMe-тира.

## Решение

- Входные форматы: **safetensors (HF)** и **GGUF**.
- Целевой формат для NVMe-тира: собственный **stell-tier layout** (спецификация — ADR-12).
- Квантованное профильное хранение: NVFP4 / W4A16 — как отдельные варианты лоадеров
  и конвертеров, не как отдельные «входные» форматы.
- Экзотические форматы — только через конвертер в один из перечисленных.

## Альтернативы

- **Поддержка произвольных экзотических форматов напрямую** — раздувает слой
  models; всё сводится через конвертер.

## Последствия

Модуль `models/weights` держит ровно 4 пути: safetensors, GGUF, NVFP4-W4A16,
stell-tier; у каждого — golden-тесты (ADR-09). Формат stell-tier зафиксирован
в ADR-12 и не меняется без ADR.

## Уточнение (round 5, задача T-20261017200354) — BF16 как входной dtype

Контракт (4 пути лоадеров, целевой формат stell-tier) не меняется; фиксация
решения planner round 5 ([Q6]→[R5], вердикт round 4: approve).

- **BF16 — допустимый входной dtype** для входных форматов (safetensors/HF).
  Целевой профиль вычислений не меняется: BF16→F16 конверсия на входе —
  по прецеденту F32→F16.
- **Конверсия — clamp-сатурация к ±65504**, не inf/NaN: значения |v| ≥ 65504
  сатурируются к ±65504 (максимум F16); inf в весах не порождается.
  Обоснование: inf в весах заражает все последующие вычисления
  (NaN-пространство) и не диагностируется в golden-логитах; clamp —
  детерминированный, видимый и наблюдаемый; реальные веса практически
  не содержат |v| > 65504 (нормы весов ≤ 10²) — сатурация это граница
  безопасности, а не искажение качества.
- **Provenance `dtype_orig`.** Конвертер/описание фиксируют исходный dtype
  весов (например `dtype_orig: bf16`) — честность профиля сохраняется:
  точка регрессии/замер знает, что было сжатие из BF16.
- **Счётчик сатураций** — в логе конвертера: число значений, подвергшихся
  clamp-сатурации (видимость границы, не скрытая замена данных).
- Требование теста: |v| > 65504 → ±65504; обычные значения побитово ==
  текущей конверсии.
