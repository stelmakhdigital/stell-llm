# ADR-01: Ядро — C++20 + CUDA 12.x (SM70)

- **Статус:** Принято (PLAN.md §3; до начала потоков A–E)
- **Связано:** ADR-08…ADR-12 (интерфейсные контракты модулей)

## Контекст

Нужен полный контроль над памятью, пулами слотов и DMA для tiering и CUDA Graphs.
Кандидат: PyTorch-стек (как у vLLM).

## Решение

Ядро рантайма — C++20 + CUDA 12.x, таргет SM70 (Tesla V100). Python — только тонкий
control-plane (serve/ui/calibrate/bench, см. ADR-11).

## Альтернативы

- **PyTorch-стек** — быстрее старт, но тянет ограничения фреймворка и не даёт
  контроля пулов слотов фиксированного размера и DMA-расписания tiering.

## Последствия

Своё ядро и свои ядра (kernels) — выше порог входа, но полная управляемость
памятью и расписанием. Все контракты модулей (ADR-08…ADR-12) пишутся как C++20
интерфейсы, за исключением стыка serve ↔ engine (ADR-11).
