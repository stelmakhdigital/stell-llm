# ADR-05: CUDA Graph для decode; фиксированные пулы; eager-фолббек

- **Статус:** Принято (PLAN.md §3)
- **Связано:** ADR-08 (слоты фиксированного размера), ADR-10 (разметка при TP/EP)

## Контекст

MoE создаёт динамический набор экспертов на шаг декода, а CUDA Graph требует
константной разметки.

## Решение

- Decode — по **CUDA Graph**, снятому на **фиксированном пуле слотов** константной
  разметки: размер слота каждой тензорной группы известен до старта графа.
- Экспертная динамика закрывается: (а) слоты фиксированного размера + DMA,
  (б) eager-фолббек внутри модуля engine, если разметка всё-таки изменилась.

## Альтернативы

- **torch.compile** — вне ядра (см. ADR-01): не даёт контроля над пулами и DMA.

## Последствия

Контракт engine ↔ tiers (ADR-08) обязан гарантировать фиксированный
`slot_bytes` каждой группы до старта графа; пере-разметка = переснятие графа.
