> Статус: заготовка. Модуль не реализован. Контракт: ADR-10 (интерфейс, CPU-эмуляция).

## Уточнения контракта (round 1, T-20261017200354)

- Мета шага (ADR-10 «Уточнение»): рассылка — фиксированный F32-пейлоад
  (8 слотов × float = 32 байта: `[шаг, размер батча, резерв…]`) через обычный
  `allgather(CommDType::F32)`; отдельный `CommDType::Meta` отклонён —
  parallel остаётся семантически нейтральным, формат слотов знает только engine.

## Уточнения контракта (round 2, T-20261017200354)

- `expert_alltoall` получает `token_elems` (элементов dtype на токен; для
  hidden `= d_model`) — ADR-10 «Уточнение round 2»; мета-структура без изменений.
- `ICommunicator::subgroup(ranks)` — подгруппа редуцирует только по своим
  ранкам (per-stage TP при pp>1); владение у родителя; эмулятор — фильтрация
  ранков, NCCL — communicator split (до GPU-окна — заготовка).
- Эмулятор при нехватке recv-ёмкости → `BufferTooSmall` (без молчаливого
  сокращения пересылки).

## Уточнения контракта (round 3, T-20261017200354)

- Протокол GPU-валидации NCCL (planner [Q1], server-env): корректность —
  пара GPU0 (V100) + GPU4 (RTX 2060), побитово == CPU-эталон; при зависании
  P2P — повтор с `NCCL_P2P_DISABLE=1` (корректность обязана подтверждаться
  и без P2P). Latency-замер — только V100↔V100 по NVLink, в более чистом
  окне, с пометкой co-tenancy. Честный PENDING (`checks=0 failures=0`)
  при недоступности карт сохранён.

## Объём (из PLAN.md §4, поток C)

- NCCL TP (dense), EP-шардирование экспертов по NVLink, PP для dense > VRAM.
- Комбинированные схемы PP×TP / PP×EP; KV-streaming между узлами.
- Бенчмарки масштабирования: TP4 dense ≥3.2× от TP1.

## Готовность

- GLM-класс на 4–8×V100-SXM2 проходит TP/EP-контуры; CPU-пути комм-паттернов
  тестируются локально без NCCL/GPU (ADR-10 §4).
