# serve — дизайн-документ (заготовка)

> Статус: заготовка. Модуль не реализован. Контракты: ADR-06 (порт 8080), ADR-11 (C ABI).

## Уточнения контракта (round 1, T-20261017200354)

- Владение строками C ABI: `char**`-выходы — malloc-строки, освобождает
  вызывающий (документировано в `capi.h`, реализовано в `engine.py`).
- `stell_step` — ABI-совместимое добавление; старт-стоп фоновой нити engine
  в ABI раунда 1 не вводится (см. ADR-11 «Уточнение»).
- Chat-шаблон: владелец — serve (линейная заглушка до готовности реестра;
  при появлении поля шаблона в описании модели — подмена без изменения
  контракта с engine).
- Маппинг `cancelled`: OpenAI `stop` / Anthropic `end_turn`; факт отмены —
  в `/metrics` (`cancelled_total`), не в семантике finish_reason
  (см. ADR-11 «Уточнение»).

## Уточнения контракта (round 3, T-20261017200354)

- Формат поля `logits` снапшота `/metrics` — строго
  `{"requests_total","errors_total","last_n_vocab","last_positions"}`;
  payload логитов (массивы) в `/metrics` запрещён — только через
  `stell_logits` (ADR-11 §4 «Уточнение round 3»). Тест serve проверяет
  наличие всех четырёх полей и отсутствие массивов; валидация формата —
  `is_valid_logits_snapshot` (`LOGITS_SNAPSHOT_FIELDS`); дашборд рендерит
  строго 4 KV (фиксированная схема `LOGITS_FIELDS` в `app.js`).
- Quality-gates `--live` (HumanEval-32): исполнение сгенерированного кода —
  process-sandbox (`src/bench/stell_bench/code_sandbox.py`): RLIMIT_CPU=5с /
  RLIMIT_AS=512 МиБ / RLIMIT_NOFILE=64, wall-таймаут 10с (kill+reap),
  изолированный temp-dir, пустой env; классификация исхода ok/timeout/error.
  **Честная граница: process-sandbox, НЕ security-граница** (права
  пользователя, сеть не отключается; unprivileged seccomp/namespaces
  недоступны — контейнерная изоляция вне рамок). Конвейер кейса: жадное
  декодирование (≤32 токенов) → `extract_code` (первый markdown-fence, иначе
  весь ответ) → исполнение против test-кейса задачи + `check(entry_point)` →
  accuracy = доля exit 0; протокол-константы HUMANEVAL_PROMPT_TOKENS=64 /
  HUMANEVAL_MAX_STEPS=32 фиксируются в report.json.

## Уточнения контракта (round 5, T-20261017200354)

- `stell_logits` `positions:"last"`: JSON-контракт §2 ADR-11 не меняется;
  уточнение стоимости — на стороне engine (проекция только последней
  позиции, O(vocab) — см. ADR-11 «Уточнение round 5» и дубль в engine.md).
  Serve-контур PPL (incremental-last в quality-gates, fixup round 4) —
  без изменений; побитовая эквивалентность движкового last-пути —
  обязательна (тест).

## Решения round 6 (T-20261017200354, planner [Q1]/[Q3], вердикт round 4: approve)

- **Черновик «eval-сессия с переиспользованием KV»** ([R5]): в `request_json`
  `stell_logits` — опциональное поле контекста переиспользования KV;
  вызовы без поля — прежнее поведение (ABI-совместимо, поля только
  добавляются); явный триггер подъёма в приоритет — wall PPL на реальной
  >VRAM-модели > 1 ч в [R4] round 6; до триггера ABI не меняется;
  черновик-документ, не реализация (ADR-11 «Черновик round 6»).
- **Вердикт по цели §4 — только по формализованному критерию** ([R3]):
  p95 ≤ 5 мс и prefetch ≥ 60% валидны лишь при (а) модель > VRAM-бюджета
  (hit-rate < 1 обязателен), (б) чистое окно или честная co-tenancy-пометка
  с профилем остатка, (в) per-group семантика паузы, (г) матрица
  {O_DIRECT, buffered} × {k=1, k=4}; co-tenancy-замеры крошечных моделей
  НЕ валидны как вердикт (server-env.md «Формализованный критерий
  вердикта §4 ([R3] round 6)»; дубль в tiers.md). Serve публикует
  значения (`/metrics`), пороги проверяет bench-харнесс — ADR-11 §4
  без изменений.
