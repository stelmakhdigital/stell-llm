# models — дизайн-документ (заготовка)

> Статус: заготовка. Модуль не реализован. Контракты: ADR-09 (схема/реестр), ADR-03, ADR-12.

## Уточнения контракта (round 1, T-20261017200354)

- GGUF-нейминг (ADR-09 «Уточнение»): `source_pattern` — в конвенции имён входного
  формата, лоадер сравнивает буквально; GGUF-описания генерируются конвертером
  с нативными именами тензоров формата GGUF (`blk.*`; канон ADR-09),
  без неявного HF↔GGUF маппинга.
- Golden: режим фикстуры — `greedy` (argmax); bench-«T=1» = `temperature=1.0`
  (не greedy) — см. ADR-09 «Уточнение».
- Известное упрощение: конвертер пишет `n_tensors = n_groups` (см. ADR-12
  «Уточнение»); `header_crc32` конвертера — байты [0x00..0x2C) (канон ADR-12).

## Уточнения контракта (round 2, T-20261017200354)

- Канон NVFP4/W4A16 — **block32** (ADR-09 «Уточнение round 2»): квантованные
  группы — только линейные веса; F32/F16-группы — норм/router/layernorm;
  dtype — атрибут `tensor_group`, лоадер читает dtype из группы без
  fallback-догадок. Group-16-фикстуры kernels — legacy (не-контракт).
- Прод-токенизатор: byte-level BPE реализуется здесь (`ITokenizer`,
  `tokenizer.json` в каталоге модели, описан в реестре); инжект в engine —
  `Scheduler::set_tokenizer`; byte-fallback engine остаётся контрактной точкой.

## Уточнения контракта (round 3, T-20261017200354)

- Потоковая конвертация в stell-tier: `StellTierConverter::convert_streaming()`
  — память O(максимальной группы) (одна группа + source-буфер, не O(размера
  модели)); flush по группам (порог `flush_group_bytes`, дефолт 8 МиБ);
  атомарная финализация `tmp → rename` + self-check собственным reader'ом;
  fixup индекса (CRC-placeholder до данных, перезапись 64-байтовой записи
  после каждого слота — правило ADR-12 «Уточнение round 3»).
- `StellTierWriterConfig` — параметры тиров принимаются извне (согласованы
  с `TierConfig` tiers; границы тиров задаёт tiers-конфиг); writer только
  валидирует план: группа не влезает в `vram_slot_size` → `SchemaMismatch`
  (fail-fast); `ram_capacity` в layout семантики не имеет; `slot_align`/
  `index_align` фиксированы layout v1 (4096/512), кастомные значения →
  `SchemaMismatch` (новая версия формата — только через ADR-12).
- Публичный CLI `stell_convert_streaming <desc.json> <source> <out_dir>
  [--vram-slot-size B] [--ram-capacity B] [--flush-mb N]`; старый
  материализующий `convert()` не тронут (сравнение/совместимость).
- Прогон на реальных весах — через env `STELL_R7_REAL_WEIGHTS_DIR`
  (каталог safetensors-шардов HF) + `STELL_R7_REAL_DESC_JSON` (описание
  ADR-09 схемы 1.0), без правки кода; веса в git не попадают.

## Решения round 5 (T-20261017200354, planner [Q4]/[Q5] → [R3]/[R4], вердикт round 4: approve)

- **Per-layer план** ([R3]): слои одного описания могут иметь разные
  op-профили — слой с `mlp.router`/expert-группами → MoE-контур, без —
  dense ffn путь (маршрутизация per-layer в ops_runner); однородный план —
  частный случай (дефолт не меняется, версия `schema` не меняется);
  непокрытые конфигурации (частичный набор MoE-групп) — честный
  `SchemaMismatch`, не тихий неверный план. Обоснование: реальные
  Qwen2Moe-классы (SmolLM2-360M-MoE: 3 плотных из 31) массово содержат
  плотные первые слои; фильтр однородности отбрасывает большинство
  реальных чекпоинтов (ADR-09 «Уточнение round 5»).
- **`ffn.shared`** ([R4]): shared-expert — dense-FFN группа (gate/up/down);
  выход суммируется с routed-экспертами слоя. Новая операция ядра не
  вводится — суммирование в интерпретаторе плана; отсутствие группы в
  описании — поведение без изменений (обратная совместимость планов,
  перегенерация не требуется). Обоснование: Qwen2Moe/OLMoE содержат
  shared-expert с постоянным аддитивным вкладом в выход FFN; движковый
  MoE-контур его не содержал (ADR-09 «Уточнение round 5»). Требование:
  фикстура Qwen2Moe/OLMoE-класса со shared-экспертом — логиты ==
  референсу плана (побитово на CPU).
- **BF16 → F16 с clamp-сатурацией** ([R5]): BF16 — допустимый входной dtype;
  конверсия сатурирует к ±65504 (максимум F16), не inf/NaN; provenance
  `dtype_orig` в описании/конвертере; счётчик сатураций в логе конвертера
  (ADR-03 «Уточнение round 5»). Тест: |v| > 65504 → ±65504; обычные
  значения побитово == текущей конверсии.

## Решения round 6 (T-20261017200354, planner [Q5]/[Q6], вердикт round 4: approve)

- **`ffn.shared.gate_scalar`** ([R1]): описание Qwen2Moe-класса содержит группу
  из тензора `mlp.shared_expert_gate` (форма `[1, d_model]`, d_model→1);
  семантика гейта и фиксированный порядок суммирования — ADR-09
  «Уточнение round 6»; отсутствие группы — прежнее поведение; частичный
  набор (gate без `ffn.shared` или наоборот) → SchemaMismatch. Требование:
  реальный tiny-qwen2moe — описание покрывает gate, логиты == референсу
  плана побитово; обнуление gate-веса даёт предсказуемое изменение.
- **Перегенерация описаний с `dtype_orig`** ([R2]): описания, используемые
  гейтами (минимум tiny-qwen2moe), перегенерируются с полем `dtype_orig`;
  слоты/логиты до/после — побитово идентичны (конверсия не менялась);
  правило: **точки регрессии обязаны иметь полный provenance**
  (`dtype_orig`, host/дата/UTC/коммит, `co_tenancy`, `io_mode` и др.) —
  server-env.md «Точки регрессии обязаны иметь полный provenance
  ([R2] round 6)»; для будущих конверсий поле обязательно по умолчанию.
