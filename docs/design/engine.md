# engine — дизайн-документ (заготовка)

> Статус: заготовка. Модуль не реализован. Контракты: ADR-08, ADR-09, ADR-10, ADR-11.

## Уточнения контракта (round 1, T-20261017200354)

- Слой→группы: engine — единственный вызывающий `set_plan` + `set_layer_map`
  (пара, «холодная» дисциплина, до переснятия графа); `layout_version` —
  детерминированный хэш состава плана (`ExecutionPlan`), сверяется
  `DecodeExecutor` — см. ADR-08 «Уточнение».
- Мета шага: ранг 0 рассылает 8×F32 слотов через `allgather` (ADR-10 «Уточнение»).
- Sampling: «T=1» = `temperature=1.0` (не greedy); greedy — отдельный явный
  режим golden-контракта (ADR-09 «Уточнение»).

## Уточнения контракта (round 2, T-20261017200354)

- `stell_logits` (ADR-11 «Уточнение round 2»): ABI-совместимое расширение —
  request `{"prompt_tokens":[...], "positions":"last"|"all"}`, ответ
  `{"logits":[[...]], "n_positions", "n_vocab"}` (финальный слой, до softmax);
  возврат 0/-1; malloc-строки, free() — на вызывающем.
- `stell_cancel` — конвенция create/submit: 0 = успех, -1 = ошибка
  (сессия не найдена/закрыта); маппинг из `Scheduler::cancel → bool` — в
  capi-слое.
- Прод-токенизатор — byte-level BPE в `src/models` (токенизатор не знает
  `tokenizer.json`); byte-fallback engine остаётся контрактной точкой;
  инжект — существующий `Scheduler::set_tokenizer`.

## Уточнения контракта (round 5, T-20261017200354)

- `stell_logits` `positions:"last"` — проекция только последней позиции:
  движок не материализует логиты всех позиций промпта (стоимость O(vocab),
  не O(prefix×vocab); прежний путь скрыто материализовал всю матрицу
  n_positions × n_vocab ≈ 300+ МиБ на вызов для vocab≈152К). JSON-контракт
  ADR-11 §2 не меняется; побитовая эквивалентность с прежним last-путём —
  обязательна (тест на mini_dense и mini_moe, промпт ≥ 64 токенов;
  wall-время 128 last-вызовов ≤ 2× одного полного forward — в логе теста).
  KV-state-инкрементальность (устранение пересчёта префикса) — изменение
  ABI-семантики — не заводится, будущая задача (ADR-11 «Уточнение round 5»).

## Решения round 6 (T-20261017200354, planner [Q5]/[Q1], вердикт round 4: approve)

- **`ffn.shared.gate`** ([R1]): скалярный сигмоид-гейт shared-эксперта —
  `sigmoid(dot(w_gate, hidden)) × shared_ffn_out`, суммирование с routed
  в фиксированном порядке (`routed_sum`, затем добавление gate-вклада —
  для побитового референса); группа из тензора `mlp.shared_expert_gate`
  (d_model→1); отсутствие группы — прежнее поведение; частичный набор →
  SchemaMismatch; реализация в ops_runner, новое ядро не вводится
  (ADR-09 «Уточнение round 6»; дубль в models.md).
- **Черновик «eval-сессия с переиспользованием KV»** ([R5]): опциональное
  поле `request_json`; вызовы без поля — прежнее поведение
  (ABI-совместимо); триггер подъёма в приоритет — wall PPL на реальной
  >VRAM-модели > 1 ч в [R4] round 6; до триггера ABI не меняется;
  черновик-документ, не реализация (ADR-11 «Черновик round 6»;
  дубль в serve.md).

## Объём (из PLAN.md §4, поток A)

- Планировщик continuous batching на ≥8 сессий; пулы слотов фиксированного размера.
- CUDA Graph по константной разметке + eager-фолббек (ADR-05).
- Спекулятивный контур: драфт + FP32-верификация + автоотключение по калибровке.
- KV-streaming для длинного контекста.

## Готовность (критерии PLAN.md §4)

- Ядра проходят операторные replay-тесты; dense в 1 GPU и MoE с фиксированным пулом
  экспертов в 1 GPU через engine; CPU-пути тестируются без GPU.
